# AgentBay vs Zep

## Short version

Zep is strong when memory is a temporal knowledge graph over users, sessions, and business data. AgentBay is for coding agents: project-scoped memory, team governance, transparent retrieval scorecards, and MCP-native install paths.

## Comparison

| Capability | Zep | AgentBay |
|---|---|---|
| Primary memory model | Temporal knowledge graph | Hybrid retrieval plus scoped coding-agent memory |
| Main data shape | Users, sessions, groups, facts, entities | Projects, teams, agents, knowledge tiers, tags, aliases, graph links |
| Best fit | Application agents over user/business context | Coding agents working across repos and teams |
| Retrieval surface | Graph search and memory context APIs | MCP tools and SDK calls |
| Graph capability | Core product strength | Graph retrieval plus vector, lexical, tag, and alias signals |
| Scope hierarchy | User/session/group oriented | Project / team / public scope |
| Teams + role-based permissions | App/platform dependent | [Teams surface](https://aiagentsbay.com/teams) |
| Published scorecards | Not mirrored here | [LOCOMO and AgentBay-native scorecards](../scorecards/) |

## When Zep is a better fit

- Your product needs temporal graph memory over users, sessions, and business facts.
- You want memory context strings and graph search APIs for an application agent.
- The memory layer is embedded in your app, not primarily in developer tooling.

## When AgentBay is a better fit

- Your memory problem is engineering context across coding agents and teammates.
- You need project/team/public scope and governance around shared memory.
- You want retrieval claims backed by public scorecards with ablation rows.

GBrain is one user, one brain. AgentBay is teams, projects, governance.
